# LLM 优化与固定小批量对照

日期：2026-10-20（Asia/Singapore）。模型：`deepseek-flash`。

默认策略恢复了本批离线排序表现，没有证据表明需要默认开启模型筛选或自动查询扩展。

## 相同20个会话

按 scenario 分层，以 seed=20261020 固定抽取20个公开样本：Buying 8、Browsing 8、Intent Override 3、Boundary 1。抽样仅使用场景和样本ID，不根据历史命中挑选。各组使用同一官方模拟器、最多10轮、相同评分公式，关闭离线回退。

| 方案 | TechnicalScore | Hit@10 | MRR | MTTC |
| --- | ---: | ---: | ---: | ---: |
| 旧 ReAct（同20样本历史记录） | 0.765500 | 90.0% | 0.601667 | 4.250 |
| 原离线版 | 0.888167 | 100.0% | 0.713889 | 2.300 |
| LLM 解析＋原文校准＋原排序 | 0.888167 | 100.0% | 0.713889 | 2.300 |
| 优化 ReAct（默认） | 0.888167 | 100.0% | 0.713889 | 2.300 |
| 优化 ReAct＋自动扩展 | 0.886667 | 100.0% | 0.705556 | 2.250 |

旧 ReAct 一行来自上次200样本记录中的同一批ID，无需再次调用API；它是历史参考，不是同时重新运行的随机性对照。当前各组相同解析请求复用响应，减少模型采样差异与费用。缓存回放不计入新消费。

## 按五项要求完成的修改

1. 推荐与追问可同时返回。正文中的提问必须使用结构化字段，最终追问按 `ask_attribute` 统一生成，防止正文问袖长、字段却写 other。
2. 默认输出最多10个本地排序候选。模型不再只选两三项或改变顺序；硬预算仍排除价格未知、无效或超上限的商品，并从更深候选池补足。LLM筛选仅作为显式实验。
3. 原始英文需求词句、类别与累计条件用于原始检索和特征计算。翻译/同义词是独立召回路线，经RRF融合后统一排序。自动扩展默认关闭；ReAct明确发起的搜索仍可加入额外路线。
4. 复用原澄清与首轮策略。信息充分走一次解析后的快速路径；候选不足或冲突才进入ReAct循环。近似价格around不被错误变成硬上限，显式替换不会带回已作废偏好。
5. 提供固定分层抽样、检查点、请求缓存、请求上限和逐会话日志，并对扩展/筛选分别测试。原evaluator和评分公式未改。

## 扩展与筛选的单独观察

自动扩展相对默认组的20会话 TechnicalScore 变化为 -0.001500，因此暂不默认开启。
另有 37 个相同检索上下文的零API成本对照：原路线目标进入Top10共 27 次，加入扩展后 29 次，新增 2、丢失 0。召回覆盖改善不代表最终排序MRR或完整会话分数一定改善；这些上下文也来自扩展组本身的路径。

只对预先固定的5个会话启用LLM筛选。相同5会话的自动扩展对照分数为 0.836000，增加筛选后为 0.898000；两组Hit@10均100%。但逻辑tokens约从 18,262 增加到 457,288，约 25.0 倍。5例不足以证明稳定收益，筛选仍默认关闭，未实施LLM重排。

## 费用与验证范围

- 本次开发、修复复验、所有小批量对照及2轮中文冒烟合计新增模型请求 117 次，输入 694,141、输出 19,178 tokens，总计 713,319。费用以供应商账单为准。相同响应缓存反复回放不再次收费；记录中的API调用次数指逻辑模型请求，传输重试仍可能另发HTTP请求。
- 默认ReAct在同20样本中的逻辑tokens（新响应＋回放）为 76,176；旧ReAct同20样本已知tokens为 1,050,011，减少约 92.7%。这比较的是同会话的已知请求用量，不把缓存的零新费用当作部署成本。
- 默认ReAct本批 46 个用户轮均走快速路径。因此结果证明的是回归保持，不是自主探索能力的提升。探索工具的实际调用由5例筛选实验覆盖，不能替代更多低召回/冲突场景的独立验证。
- 完整测试套件54/54通过；两轮中文真实API验证了推荐＋中文追问、硬预算、换品类清空。原离线200样本回归仍为0.904600，不消耗API。
- 开发中修复的解析协议问题保留了日志；最终表只使用最终代码的零异常记录，没有挑选早期较高的分数。
- 公开样本主要是规则可解析的干净文本；原文校准也复用了规则能力。这不是纯LLM解析的独立收益证明。20样本均已用于本轮方案选择，不能当成独立留出集，也不能外推成新版200样本分数。

## 复现

```bash
python3 scripts/compare_llm_modes.py --env-file .env \
  --output artifacts/llm-ablation --samples 20 --filter-samples 5 \
  --workers 2 --max-api-calls 250
```

默认运行 offline、llm_parse、react、react_expansion，并对5例额外运行react_llm_filter。相同输出目录只在样本、模型和源码指纹一致时恢复。原始逐会话记录、缓存、中文冒烟与summary保存在本地忽略的 `artifacts/llm-optimization-20261020/`，不含API Key。
